# ADR 006: Site-visit lifecycle, Home, entity search and job-oriented navigation

## Status
Accepted and implemented in Slice 3 (decisions D6, D12; findings in `docs/audit/2026-10-14/03_PRODUCT_WORKFLOW_PIPELINE_INVENTORY.md`).

## Context
Visits could be created by API only: there was no booking screen, no reschedule, no outcome, no reminder, and the calendar was a read-only list.
The first page after sign-in showed counts that did not say what to do. Search found pages, not records. Navigation was organised by
module name rather than by the job a person is doing.

## Decision
1. **A visit is a versioned record with a lifecycle**: scheduled/confirmed, then completed, cancelled or no-show. `viewings.version` backs ETag/If-Match so a
   reschedule made on a stale copy is refused (412) instead of overwriting a colleague. Outcome (fixed catalogue in code), note, close time and cancel reason are columns.
2. **Overlap and eligibility are enforced by the server in the same transaction as the write** (property row and agent checked together; 409 `SLOT_UNAVAILABLE`).
   Per D6 a visit may be booked or moved only while the unit is available or under offer and the lead is live; reserved, sold, rented, inactive and archived units
   and archived leads are refused (422). Agents may only act on visits of their own leads (404 otherwise); handing a visit to another agent is manager-only.
3. **The reminder is a real task**, not a screen-only item: `viewings.reminder_task_id` (composite tenant FK, `ON DELETE SET NULL (reminder_task_id)`),
   created through `TasksService.createInTx` with dedupe key `viewing:{id}:reminder`, moved on reschedule and closed on cancel/complete. Because it is the lead's next
   follow-up, Home and the team counts exclude reminder tasks and show the visit once, as a visit.
4. **Completing a visit never moves the lead.** The response carries `suggestedStage` ("Site visit done", key `viewing_completed`) and the person chooses.
   An optional follow-up task is created exactly once (dedupe `viewing:{id}:followup`).
5. **Calendar file (.ics)** is generated by a small pure builder (UTC, folded at 75 octets, escaped, `VALARM`, stable UID). It contains time, place, property and the
   buyer's name only, never phone or e-mail.
6. **Next step is derived, not typed**: `LeadsService.get` computes `nextStep` (reply, reply overdue, record visit, visit, task, plan) from the lead's own rows.
7. **Home** (`GET /home`) is a read model with permission-gated sections (`null` when the role cannot see it). "Today" is the workspace time zone. Every number equals
   the length of the list beneath it. The weighted forecast is labelled as the owner's own estimate.
8. **Search** (`GET /search`) is a single permission-checked endpoint: two to a hundred characters, escaped `ILIKE`, phone matched on digits, five per kind,
   kinds omitted when the role lacks read, own-scope applied to leads and tasks, archived excluded. It is not trigram-indexed (see limits).
9. **Navigation follows D12**: Home / Sales / Inventory / Marketing / Automation / Analytics / Administration. Dashboard and Calendar screens were removed;
   their addresses redirect (`/dashboard` to `/`, `/calendar` to `/tasks?view=calendar`). Tasks and calendar share one page with a List/Calendar toggle.

## Consequences
- Display times in the web app use the viewer's browser time zone; Home's "today" uses the workspace zone. When the two differ, an item near midnight can appear on
  different days in the two places. The server stores UTC, so no data is affected. (Home's day bounds are computed by Postgres in the workspace zone and are tested on the 23-hour and 25-hour days of New York; the browser side relies on the platform zone database and is not separately tested.)
- A visit's reminder task can be completed or deleted by hand; the visit keeps working and the FK nulls the reference.
- Marketing route renames (`/marketing/*`) were not part of this slice; only the grouping changed.
- Adding a second reminder (for the buyer) belongs with Slice 7 (communications) and needs provider accounts.
